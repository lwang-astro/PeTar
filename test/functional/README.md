# Functional Smoke Test Layer (Pre T1-T4)

This directory adds a **functionality correctness** layer before the physics-focused validation in `test/validation`.

Goals:

1. Build/compile matrix sanity check across major features.
2. One very fast simulation run per feature case.
3. Analysis tools pipeline check without runtime errors.

## Scope And Positioning

- `test/validation` (T1-T4): checks physical behavior and numerical reasonability.
- `test/functional` (this layer): checks software functionality and workflow continuity.

Use this layer first, then run T1-T4.

## Case Matrix

Case definitions are stored in [test/functional/functional_matrix.json](test/functional/functional_matrix.json).

Current first-pass cases:

- `std` (standard run; no interrupt mode)
- `merger`
- `bse`
- `galpy`
- `bse-galpy`
- `agama` (optional; requires `AGAMA_CONF_FILE` environment variable)

Naming rule:

- `std` means the standard no-interrupt baseline run.
- `merger` means `interrupt_mode=merger`, i.e. the simple collision/interruption mode.
- These two meanings must not be mixed in reports or test configuration.

All cases use deterministic tiny IC generated by [test/validation/make_ic.py](test/validation/make_ic.py), with short run duration (`t_end=10`, `dt_out=1`) to keep turnaround fast.

For the current default IC case (`functional_mcluster_dual_merge_smoke`):

- The current workflow assumes `mcluster -u 1`, so generator output is interpreted as `Msun`, `pc`, `km/s`.
- The IC writer keeps mass in `Msun`, position in `pc`, and velocity in `km/s`.
- Under `petar -u 1` (target unit: `Msun`, `pc`, `pc/Myr`), `petar.init` must use `-v 1.022712165045695` (`km/s -> pc/Myr`).
- This is the recommended path because it keeps the final IC directly in PeTar's standard astrophysical unit system.
- In principle one may keep another length unit such as `kpc` and provide a matching `G` with `petar -G`, but then all unit-sensitive options in BSE/Galpy/Agama and post-processing must be converted consistently; functional tests do not use that advanced path.

## How To Run

From repo root:

```bash
python3 test/functional/run_functional_smoke.py --phase all
```

Run only build matrix:

```bash
python3 test/functional/run_functional_smoke.py --phase build
```

Run only selected cases (after build/install done):

```bash
python3 test/functional/run_functional_smoke.py --phase run --cases merger,bse,galpy
```

Enable optional Agama case:

```bash
export AGAMA_CONF_FILE=/path/to/MWpotentialHunter24_rotspiral.ini
python3 test/functional/run_functional_smoke.py --phase run --cases agama
```

If `AGAMA_CONF_FILE` is not set, the runner now defaults to
`sample/MWPotentialHunter24_rotspiral.ini` automatically.
Set `AGAMA_CONF_FILE` explicitly only when you want to override that default.

## What Is Checked Per Case

1. `petar.init` IC conversion works for the mode (std/merger/BSE/external).
2. `petar.select --require ...` can switch to the expected binary family.
3. `petar` run can start and finish normally.
4. Analysis chain runs successfully:
   - `petar.data.process`
   - `petar.get.object.snap`
   - `petar.format.transfer.post`
5. Expected output artifacts exist (snapshot file, `data.lagr`, object extraction file).
