# Functional Smoke Test Layer (Pre T1-T4)

This directory adds a **functionality correctness** layer before the physics-focused validation in `test/validation`.

Goals:

1. Build/compile matrix sanity check across major features.
2. One very fast simulation run per feature case.
3. Analysis tools pipeline check without runtime errors.

## Scope And Positioning

- `test/validation` (T1-T4): checks physical behavior and numerical reasonability.
- `test/functional` (this layer): checks software functionality and workflow continuity.

Use this layer first, then run T1-T4.

## Case Matrix

Case definitions are stored in [test/functional/functional_matrix.json](test/functional/functional_matrix.json).

Current first-pass cases:

- `base`
- `bse`
- `galpy`
- `bse-galpy`
- `agama` (optional; requires `AGAMA_CONF_FILE` environment variable)

All cases use deterministic tiny IC generated by [test/validation/make_ic.py](test/validation/make_ic.py), with short run duration (`t_end=0.2`, `dt_out=0.1`) to keep turnaround fast.

## How To Run

From repo root:

```bash
python3 test/functional/run_functional_smoke.py --phase all
```

Run only build matrix:

```bash
python3 test/functional/run_functional_smoke.py --phase build
```

Run only selected cases (after build/install done):

```bash
python3 test/functional/run_functional_smoke.py --phase run --cases base,bse,galpy
```

Enable optional Agama case:

```bash
export AGAMA_CONF_FILE=/path/to/MWpotentialHunter24_rotspiral.ini
python3 test/functional/run_functional_smoke.py --phase run --cases agama
```

## What Is Checked Per Case

1. `petar.init` IC conversion works for the mode (base/BSE/external).
2. `petar.select --require ...` can switch to the expected binary family.
3. `petar` run can start and finish normally.
4. Analysis chain runs successfully:
   - `petar.data.gether`
   - `petar.data.process`
   - `petar.get.object.snap`
   - `petar.format.transfer.post`
5. Expected output artifacts exist (snapshot file, `data.lagr`, object extraction file).
