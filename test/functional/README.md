# Functional Smoke Test Layer (Pre T1-T4)

This directory adds a **functionality correctness** layer before the physics-focused validation in `test/validation`.

Goals:

1. Build/compile matrix sanity check across major features.
2. One very fast simulation run per feature case.
3. Analysis tools pipeline check without runtime errors.
4. Determinism where chaos matters: the `bse` case pins `--rand-seed
   1792391053081014136` (known non-grinding realization; the wall-clock
   default re-rolled a pathological tight-binary encounter on some draws,
   1.2 s … 6+ min — see `doc/restart-slowdown-cold-state-plan.md`).

## Scope And Positioning

- `test/validation` (T1-T4): checks physical behavior and numerical reasonability.
- `test/functional` (this layer): checks software functionality and workflow continuity.

Use this layer first, then run T1-T4.

If you need to trace where compact `SKILL.md` content moved, see:

- `.github/skills/petar-nbody-simulation/SKILL_CONTENT_INDEX.md`

## Case Matrix

Case definitions are stored in [test/functional/functional_matrix.json](test/functional/functional_matrix.json).

Current cases:

- `std` (standard run; no interrupt mode)
- `merger`
- `dsm`
- `bse`
- `gasdrag` (external-hard GDF family; `--gdf-hard-mode 1`; also checks the `[prefix].par.gasdrag` / `[prefix].par.exthard` model-parameter artifacts)
- `std-restart` (two-phase run: fresh run to `restart_t_end`, then the canonical restart form `petar -p <prefix>.par -i 0 ... <last_snapshot>` to `t_end`; checks that new snapshots appear and the final cadence index is reached)
- `sevn` (optional; skips when SEVN or its table set is unavailable)
- `galpy`
- `bse-galpy`
- `bse-agama` (optional; requires `AGAMA_CONF_FILE` environment variable)

Naming rule:

- `std` means the standard no-interrupt baseline run.
- `merger` means `interrupt_mode=merger`, i.e. the simple collision/interruption mode.
- These two meanings must not be mixed in reports or test configuration.

All cases use deterministic tiny IC generated by [test/validation/make_ic.py](test/validation/make_ic.py), with short run duration (`t_end=10`, `dt_out=1`) to keep turnaround fast.

ICs are matched to the mode's merge channel (contact binaries without a merge channel stall the AR integrator in million-step loops):

- `functional_mcluster_smoke` (default): Plummer cluster with **10 primordial hard binaries** (mcluster members written first as adjacent pairs; `petar -b 10`); used by `std`, `gasdrag`, `std-restart`, `galpy` — group/binary artifacts carry real records without contact-binary pathologies.
- `functional_mcluster_pair_smoke`: binary-free cluster with the collision pair written as the FIRST member pair (`petar -b 1`); used by `merger` and `dsm` — **both interrupt paths silently hang at t=0 when the pair is NOT pre-marked as a member pair** (dumps preserved in the case dirs; see lessons 2026-10-17). Primordial-binary coverage for the collision family must wait for that interrupt-path fix.
- `functional_mcluster_dual_merge_smoke`: injects ultra-compact BSE target binaries, a hyperbolic merger pair, and a 27 Msun single; used by `bse`, `bse-galpy`, `bse-agama` (BSE merges the contact binaries at the first interrupt).
- `functional_sevn_cluster`: single stars inside the SEVN gold-table mass grid; used by `sevn`.

Binary analysis coverage is distributed per mode instead of a dedicated case: the default ICs contain binaries (injected or dynamically formed), and every case runs with `--write-group-info 2`, so binary/group artifacts (`<snap>.binary`, `<prefix>.group[.rank].n<N>`; the rank segment is omitted for single-rank runs) and their readers are exercised under each interrupt/external combination. Binary physics contracts belong to `test/validation`, not here.

## Tool Coverage

Core chain, every case: `petar.init` → `petar.select` → `petar` → `petar.data.process` → `petar.group.dedup` (when group files exist) → `petar.get.object.snap` → `petar.format.transfer.post` → `petar.movie`, plus mode-correct Python readback (including `GroupInfo`).

Per-case extra tools (matrix key `tool_smokes`; mutating tools run on scratch copies):

| Case | Extra tools |
|------|-------------|
| `std` | `petar.find.dt` (pre-run tuning), `petar.data.gether` (legacy gather), `petar.<family>.format.transfer` (binary↔ASCII snapshot conversion) |
| `std-restart` | `petar.read.par`, `petar.update.par` (legacy par migration), `petar.data.clear` (legacy event trimming) |
| `bse` | `petar.bse` (standalone stellar-evolution smoke) |

Not covered here by design: dump-replay tools (`petar.hard.debug`, `petar.dump2test` — healthy runs produce no dumps), dev test binaries (`petar.hard.test`, `petar.pn.test`, `petar.external.test`), external-potential map generation (`petar.external.*`), `petar.galev.process`, `petar.<mode>.get.init.binary`, and the `mobse`/`bseEmp` standalone variants (need track files).

For the current default IC case (`functional_mcluster_smoke` and its variants, all produced by `mcluster -u 1`):

- The current workflow assumes `mcluster -u 1`, so generator output is interpreted as `Msun`, `pc`, `km/s`.
- The IC writer keeps mass in `Msun`, position in `pc`, and velocity in `km/s`.
- Under `petar -u 1` (target unit: `Msun`, `pc`, `pc/Myr`), `petar.init` must use `-v 1.022712165045695` (`km/s -> pc/Myr`).
- This is the recommended path because it keeps the final IC directly in PeTar's standard astrophysical unit system.
- In principle one may keep another length unit such as `kpc` and provide a matching `G` with `petar -G`, but then all unit-sensitive options in BSE/Galpy/Agama and post-processing must be converted consistently; functional tests do not use that advanced path.

## How To Run

From repo root:

```bash
python3 test/functional/run_functional_smoke.py --phase all
```

Run only build matrix:

```bash
python3 test/functional/run_functional_smoke.py --phase build
```

Run only selected cases (after build/install done):

```bash
python3 test/functional/run_functional_smoke.py --phase run --cases merger,bse,galpy
```

Enable optional Agama case:

```bash
export AGAMA_CONF_FILE=/path/to/MWpotentialHunter24_rotspiral.ini
python3 test/functional/run_functional_smoke.py --phase run --cases agama
```

If `AGAMA_CONF_FILE` is not set, the runner now defaults to
`sample/MWPotentialHunter24_rotspiral.ini` automatically.
Set `AGAMA_CONF_FILE` explicitly only when you want to override that default.

## What Is Checked Per Case

1. `petar.init` IC conversion works for the mode (std/merger/dsm/BSE/SEVN/external).
2. `petar.select --require ...` can switch to the expected binary family.
3. `petar` run can start and finish normally (`--write-group-info 2` enabled so binary group files are produced).
4. Analysis chain runs successfully:
   - `petar.data.process`
   - `petar.group.dedup` (when group files exist; output `<file>.dedup`, input untouched)
   - `petar.get.object.snap`
   - `petar.format.transfer.post`
   - per-case extra tools (`tool_smokes`, see Tool Coverage)
5. Expected output artifacts exist (snapshot file, `data.lagr`, object extraction file, plus per-case `expect_files` such as gasdrag model-parameter files).
6. Python readback with mode-correct dtypes: `Particle`/`Binary`/`GroupInfo`/lagrangian/escaper and the stellar-event record classes (`SSETypeChange`, `BSEKick`, ... switch to SEVN columns via `interrupt_mode`). Each readback also asserts the artifact's physical format (text vs binary sniff via `petar.detectAsciiFile`), so a writer format flip fails the case instead of surfacing as reader confusion. The authoritative file → format → reader mapping is the SKILL "File-Type → Reader-Class Quick Reference" table (`.github/skills/petar-nbody-simulation/SKILL.md`) with worked patterns in `assets/data-readback-patterns.md` — keep all three in sync when a writer format changes.

## Runtime Behavior Notes

### Step timeout

Every step runs under a wall-clock limit (matrix global `step_timeout_s`, default 1800 s; covers solver runs, builds, preflight, and tool smokes). A step that exceeds it is killed and fails the case with exit code -9 and a `[timeout]` marker in the case log — silent zero-output hangs (see lessons 2026-10-17) are then bounded instead of running for tens of minutes.

### DSM mode

- DSM smoke runs use `--detect-interrupt 1 --dsm-new-star-mode 0` by default for stability.
- Interrupt readback (merger and dsm): `data.interrupt` is an ASCII stream read strictly via `petar.InterruptBinary(...).loadtxt` — column mismatches fail the case.

### Movie checks

To make warning exposure deterministic, functional movie checks are run with `--n-cpu 1`.

### Warning grading in reports

- Snapshot structure and dtype/alignment mismatches are treated as blocking failures.
- Common ffmpeg macro-block resize warnings from `petar.movie` are treated as non-blocking warnings and still recorded in reports.

### Agama behavior

- If `AGAMA_CONF_FILE` is not set, the runner defaults to `sample/MWPotentialHunter24_rotspiral.ini`.
- Users can override this by explicitly setting `AGAMA_CONF_FILE`.

### SEVN behavior

- The `sevn` case is optional: it skips when the SEVN library is not installed (the build script reports a skipped `sevn` tag) or when no SEVN table set resolves.
- Tables are resolved like `sample/star_cluster_plummer_N1k_binaries_sevn.sh`: `SEVN_TABLES` env > gold table set next to the `--tables` default baked into the selected binary > `SEVN_DIR` source checkout.
- Its IC (`functional_sevn_cluster`) uses single stars with masses inside the gold MIST grid (0.7-80 Msun); binary-rich SEVN ICs can abort at t=0 (see the sample script notes).

### Restart behavior

- Every case runs the universal restart flow (matrix global `restart`, default `t_end_first=4`, `clear_t=3`): fresh run to `t_end_first` → `petar.data.clear -t <clear_t>` → canonical restart (`-p <prefix>.par -i 0 ... <snapshot at the trim time>`), with three assertions: the clear keeps every record at/below the trim time and drops the rest (over-deletion, across status/group/esc/event streams), the restarted run reaches the final cadence index (progress), and no duplicate records appear afterwards (snapshot list entries, status times, event-stream lines, group records by (time, id1, id2)).
- `petar.data.clear` now also trims `<prefix>.snap.lst` and deletes the stale snapshot files beyond the trim time (single-rank group files without a rank segment are discovered as well) — before this, restarting from a snapshot older than the last written one left stale list entries that `data.process` would process twice (petar truncates `status` on restart but not the snapshot list; found 2026-10-18, fixed in `tools/data_clear.sh`).
- Post-processing runs on the merged output, so restart artifacts are validated through the same tool chain.

### Portability guard

- Required test input files should be repository-tracked files.
- Generated artifacts under output directories such as `test/out/` are runtime products, not required input assets.

## Binary-Family Preflight

Before any case runs, the runner resolves every required binary family the
same way the validation suite does: `petar.select --require ...` per family,
and when the selection fails or the selected binary's version stamp
(`<PeTar VERSION>_<SDAR VERSION>`, from `<binary> -h`) does not match the
repository, the family is reinstalled via `install_petar_major_versions.sh`
and re-selected. This prevents the stale-binary failure class (an old
installed family carrying abort paths already removed from current source).
The per-case `petar.select` step remains the workflow under test; its report
details include the selected binary path and version stamp.
